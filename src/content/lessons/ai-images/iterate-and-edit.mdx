An edit changes one thing and keeps everything else. Regenerating re-rolls everything. Most disappointment in image work comes from re-rolling when you should have been editing — the composition was right, and the whole thing was thrown away over a jacket colour.

## Edit or regenerate?

The test is one question: **if everything except this one thing stayed identical, would I be happy?**

- **Yes → edit.** The foundation is right; only one variable needs moving.
- **No → regenerate.** The subject, composition or concept itself is wrong, and no amount of tweaking will rescue it.

Editing is how finished images get finished. Regenerating is how drafts get started.

## A bad example

> **Ask:** “Same image but make it better.”
>
> Nothing is named, so everything may change. There is no way to tell whether it improved — you only get a different image to react to.

## A better example

> **Ask:** “Keep everything exactly as it is; change only the light to soft and warm, and keep the shadows where they are.”
>
> One named variable, everything else pinned. The result is comparable, and the loop can continue.

## Why it works

Generation decides every variable at once, so a re-roll resets your progress along with it. An edit holds the variables you do not mention steady while it moves the one you named — which is why edit modes exist in every serious image tool. The side benefit is a trail: accepted versions become the base for the next pass, and “go back one step” becomes possible. Change one thing per pass and you always know what caused what.

## Transfer

- Any tool with editing: prefer an edit over a re-roll when most of the image is right.
- Keep versions numbered or saved — the previous version is your undo.
- When an edit overshoots, revert and take a smaller step rather than piling on corrections.
- New projects: use the loop from the start and iteration becomes routine, not a rescue.
